Одна фраза агенту.
Готовый заказ у сервиса.

LATCH соединяет агента клиента и ваш сервис: передаёт параметры, получает точные условия, запрашивает подтверждение и оформляет заказ по HTTPS. Без дублей при повторе запроса.

Для бизнеса

Не новый магазин.
Новый способ принять заказ.

Сервис остаётся на вашем домене. LATCH лишь описывает его действия в формате, который агент клиента может проверить и вызвать.

Меньше ручных действий у клиента

Агент заполняет структурированные параметры. Клиент проверяет конкретное предложение вместо повторного прохождения формы и личного кабинета.

Один endpoint для разных агентов

Любой агент, который умеет HTTP и JSON, может использовать контракт. Node SDK и MCP bridge — необязательные адаптеры, а не ещё одна обязательная инфраструктура.

Retry не создаёт второй заказ

Idempotency-Key связывает повтор с исходным task.id. Перед последствиями сервис отдаёт точные условия и ждёт подтверждения.

Подходит для производства, доставки, бронирования и внутренних сервисов — там, где действие можно описать входными данными и точными условиями.

Сервис ещё не поддерживает LATCH?

Агент может подготовить текст приглашения со ссылкой на GitHub. Ничего не отправляет и не устанавливает автоматически.

node latch.mjs invite https://service.example

Что протокол не доказывает

  • Digest — не согласие человека.
  • Receipt — не независимое доказательство физического действия.
  • Idempotency — не гарантия exactly-once для внешних систем.
  • Для production нужны auth, защищённое хранилище и rate limits.
